# `raw_data_deposit/`

`README.md`'s Tier-1 workflow describes this folder as holding your simulated
respondents' raw export in the survey's Qualtrics format, produced by running
the actual Qualtrics instrument and cleaned into `predictions/` via `make
clean`. That workflow does not apply to this entry as written, and this file
is not a Qualtrics export — the note below explains why, and what is here
instead.

## Why there is no Qualtrics-format export

This pipeline never runs the survey through Qualtrics. Predictions are
generated by direct structured LLM API calls (Together AI, `google/gemma-4-31B-it`)
against a compiled prompt that reproduces the instrument's questions and
response scales — see `registration.md` sections B–F. There is consequently
no raw Qualtrics export to deposit here, and `make clean` was never run to
produce `predictions/team_10_T1_primary_v1.csv`.

## What is deposited instead

`final_first_valid_native_g_responses.csv` is a byte-identical copy of
`pipeline/outputs/target_production/final_first_valid_native_g_responses.csv`
— the pipeline's actual raw per-respondent, per-condition simulation output:
17,000 rows (1,000 respondents x 17 conditions, one row per respondent per
condition), on the native response scale, **before** the external
calibration recentering and support-projection steps described in
`registration.md` section G. It is the closest equivalent this pipeline has
to "your simulation's raw output," deposited here for the same transparency
purpose the Qualtrics-export convention serves for Tier-1 entries that do
use Qualtrics.

Notes on reading it:

- **Column names** follow the analysis schema in `codebook.csv`
  (`target_label`, e.g. `trust_competence_1`), not raw Qualtrics labels
  (`trust_competent_1`) — there are no raw Qualtrics labels for this entry,
  since no Qualtrics export was ever produced.
- **No demographic columns are included here.** Respondent demographics
  (`age`, `gender`, `race`, `education`, `income`, `party`, `state`, ...) are
  a fixed, condition-independent input to the simulation, not part of its
  per-condition response; they are already deposited separately in
  `pipeline/data/generated/g_personas_master.csv` and the frozen CES roster
  (`pipeline/data/derived/population/ces_production_roster_n1000.csv`,
  registration.md I.2). Join on `profile_id` to attach them to the rows here.
  Ordinary constructed composites (`trust_multidimensional`,
  `funding_perceptions`, `age_band`, and the outcome `_mean` columns) are
  also not present here, since those are computed downstream of the raw
  items in this file.
- **Row-level provenance**: `pipeline/outputs/target_production/final_submission_row_provenance.csv`
  traces every row here to its literal raw provider source file and attempt
  number, and to the corresponding row in
  `predictions/team_10_T1_primary_v1.csv`.
- **This file was not regenerated or modified for this deposit.** It is an
  exact copy of the already-frozen file in `pipeline/outputs/target_production/`;
  `make clean` was not run, and `predictions/team_10_T1_primary_v1.csv` is
  untouched.
